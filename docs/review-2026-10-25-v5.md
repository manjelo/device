# RadioSim V5 review (2026-10-25)

Scope: src/radio (all V5 files), src/hooks/useRadio.ts, src/hooks/useSound.ts, src/components (RadioView, Lcd, App, controlInfo, radioSvg, DeviceDetails, InfoPanel, ControlLegend), src/styles/app.css, src/assets/radio/*.svg, the tests (src/radio/*.test.ts, src/components/*.test.*, e2e/radio.spec.ts), and docs (device-functionality-v5, research-v5, architecture V5 section, README, src/radio/README). Read-only. No build, test, lint, or Playwright run was done by this review.

Owner status: no build, test, or lint result was reported for V5. The repo has no commits and every file is untracked, so the approved SVG baseline could not be diffed. Layout and rendering claims are checked by reading CSS and arithmetic, not by rendering.

## Summary

The reducer is consistent with its docs for the paths traced: power-off clears every transient field, menu cursors stay in bounds, frequency limits and digit handling are correct, presets are never mutated, and src/radio has no React, DOM, timer, or randomness. Three behaviours need fixing before ship: PTT release is not per pointer (another pointer's lift ends simulated TX), Enter is hijacked on the details summary so keyboard users cannot open it, and the in-radio inset drops every notice on menu screens. front.svg records a "V5 proportion pass" that changed the approved geometry, which contradicts the hard fact that the SVGs did not change; this must be confirmed or reverted. Several docs and labels overstate provenance (README menu labels, "covered by tests" claims, model identity, uncertain legends in accessible names), and no build or test pass has been reported.

**Verdict: Not ready (fix first).**

Findings: Blocker 1, Major 6, Minor 19, Nit 11.

## Checked and correct

- Reducer: power on/off clears mode, locked, unlockStage, menu, edit, pendingConfirm, overlay, notice (stateMachine.ts:159-179). Startup and off ignore keys, knobs and PTT (stateMachine.ts:146-156, 188-191, 260). Locked screen and locked flag are set and cleared together (287-299). Menu cursor is clamped and restored on CLR (244-250, 365-379). Frequency bounds: 030000 and 512000 valid, 029999 and 512001 rejected (97-103; tests 421-436). Buffer keeps leading zeros; a seventh digit is refused (301-316). Presets are copied, never mutated (454). Battery never goes below 0 (181-186). Knob and key clamps return the same object (tests).
- Confirm after a menu change: not reachable. Digit, PRE and dial keys do nothing on confirm (266-282, 350-351, 200-209).
- Determinism: no Math.random, no Date, no timers in src/radio (grep). src/radio has no React or DOM import (grep).
- Safety: no dangerouslySetInnerHTML, innerHTML, fetch, XHR, WebSocket, navigator or media API in src (grep). index.html loads only the module script and favicon. SVG files contain no script, foreignObject, image or external href (grep). SVG styles are scoped by view id, so they do not leak into the page.
- Inset geometry: front.svg:166 (x 77.7, y 211.6, w 184.6, h 40.1 in a 340x630 viewBox) matches app.css:224-229 percentages (22.85%, 33.59%, 54.29%, 6.37%).
- One frame: App passes radio.lcd to both the inset (RadioView.tsx:149) and the panel (RadioView.tsx:152); brightness is one function (Lcd.tsx:14-16).
- Keypad: no `any` or `@ts-ignore` in src. Switches over KnobId and MenuItemKind are exhaustive. The tsconfig is strict with noUnusedLocals.
- Touch targets: radioSvg.test.ts checks 44 SVG units for each button and slider; e2e/radio.spec.ts:648-697 checks 44 px at 375 px.
- Motion: no transition or animation in app.css, theme.css or the SVG styles, so no reduced-motion rule is needed.
- Known issue (PRE +/- mapped to dial on pointer path): fixed. controls.ts:28-30 and keypad.ts:16-20 send PRE to the preset action.
- Stale-closure check in useRadio: handlers use stable callbacks and refs; timers are cleared on cleanup (lines 170-190).
